## Implementation Steps

### Phase 1: Foundational — Per-fact source verification

#### Plan 1.1: Verify every original SEC fact and carry the result through preprocessing

- **Requirements:** CR-02, CR-10, CR-11, DR-04.2
- **Description:** Verify every selected original fact by accession, end date, unit, tag, and exact reported value using the SEC companyconcept response. Set verification state on that fact before quarterly preprocessing. A missing/mismatched source fact must become unavailable to verified dashboard/statistical output; do not mark it verified based solely on metadata. Keep filing-index link checks and report each fact's result.

### Phase 2: Auditable ingestion and durable run status

#### Plan 2.1: Preserve immutable raw snapshots and safely update compatibility files

- **Requirements:** FR-43, CR-08, NFR-15
- **Description:** Archive each run's raw filings, facts, segments, and price/corporate-action tables under an immutable run-specific directory while retaining the existing latest-file paths for current consumers. Write replacement files atomically so a failed write cannot truncate the last valid artifact.

#### Plan 2.2: Persist source-level sync outcomes

- **Requirements:** FR-44
- **Description:** Append structured source/run records containing run ID, source, start/end timestamps, status, record count, and error detail to a durable sync log. Keep errors explicit; do not report success for a failed fetch.

#### Plan 2.3: Refresh mutable source data without refetching immutable filings

- **Requirements:** FR-40, FR-41, FR-47, CR-08
- **Description:** Apply a 55-minute freshness limit to mutable SEC/Yahoo data used by the hourly workflow. Keep immutable filing documents cached indefinitely. Refresh price history at most once per hour, and ensure the refreshed data flows into the normal dashboard JSON/manifest build.

### Phase 3: Verification and acceptance gates

#### Plan 3.1: Add regression tests and an end-to-end data verification gate

- **Requirements:** CR-10, CR-11, DR-04.2, FR-45, FR-46
- **Description:** Add fixtures for matching and mismatching facts, make acceptance reject core values that have not passed source verification, and test that the generated outputs retain expected provenance and can be consumed by existing dashboard contracts.

## Testing Strategy

- **Application type:** Scheduled data pipeline producing static dashboard JSON and SQLite handoff.
- **Critical journeys:** SEC facts are fetched and traced; every chosen fact is independently verified; failed verification is excluded; run outputs are durably archived; source status is persisted; accepted outputs pass dashboard contracts.
- **Primary validation:** pytest fixtures for positive/negative verifier cases, existing pytest suite, full `python -m pipeline.run --mode full`, then `python scripts/acceptance_check.py`.
- **Environment:** Python dependencies from `requirements.txt`; live SEC/Yahoo/Nasdaq access is required only for the full crawler and acceptance run.
- **Test data:** Existing deterministic pytest fixtures; no financial values are invented.
- **Acceptance criteria:** Tests pass; each core dashboard value is backed by a passing verifier result; failed source checks cannot be labeled verified; each run has immutable raw artifacts and source-level status; existing JSON contracts and acceptance checks pass.
- **Known limitation:** SEC source verification does not provide an absolute guarantee against upstream errors. Adjusted-close cross-provider checks remain unverified when a real Alpha Vantage key is unavailable. Nasdaq is a secondary recent-window source, not a full-history yfinance replacement.
